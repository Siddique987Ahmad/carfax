# setup/05 — CI on pull requests

Status: planned · Phase: pre-pilot · Depends on: setup/01, setup/03

## Goal
Every pull request is checked automatically, so broken types, failing tests or a forgotten migration can't reach `main`.

## Decisions
- **GitHub Actions,** as in the tech doc.
- **Only check what changed,** using Turborepo's filter against `main`, to keep runs fast.
- **Real Postgres and Redis in CI** (service containers), so API and worker tests use the same database as production.
- **Migration check:** CI runs `drizzle-kit generate` and fails if it produces a new file. That means someone changed the schema without committing the migration.
- **`main` is protected:** checks must pass and one review is required before merging.

## Scope
**In:**
- `.github/workflows/ci.yml`: install (with pnpm cache), lint, typecheck, test, migration check, i18n check (setup/04)
- Postgres 16 and Redis service containers
- Branch protection on `main`

**Out (later items):**
- Deploys (setup/08, setup/09)
- Mobile builds (garage-app plans)

## Steps
1. Write the workflow with caching.
2. Add the service containers and test env variables.
3. Add the Drizzle migration check (once db/01 exists; skip until then).
4. Turn on branch protection.
5. Open a test PR with a deliberate type error and confirm it fails.
